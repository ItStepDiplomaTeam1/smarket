## Context

ШІ-агент Zephyros (Promin) має доступ до пошуку товарів та додавання в кошик. Для підвищення юзабіліті ми інтегруємо додаткові можливості користувача (навігація, фільтри каталогу, відгуки, порівняння всього кошика), використовуючи готові ендпоінти мікросервісів `cart_service` та `reviews_service`.

## Goals / Non-Goals

**Goals:**
- Реалізувати нові інструменти ШІ-агента на бекенді: `clear_user_cart`, `remove_item_from_cart`, `compare_cart_stores`, `get_product_reviews`, `create_product_review`.
- Оновити схему відповідей `ZephyrosResponse` на бекенді та фронтенді, підтримавши нові типи кнопок: `navigate` та `apply_filters`.
- Додати у фронтенд-компонент `AiChatWidget.tsx` обробку кліків по нових кнопках:
  - `navigate`: викликає перехід по роуту React-Router.
  - `apply_filters`: оновлює стан фільтрів у каталозі та закриває вікно чату.
- Реалізувати інтерактивні кнопки дій безпосередньо у відповідях асистента (наприклад, кнопка порівняння кошика у верхньому меню або кнопка переходу).

**Non-Goals:**
- Зміна структури баз даних (БД схеми) сервісів `cart_service` чи `reviews_service`. Усі операції виконуються через наявний REST API.
- Переписування дизайну віджета чату. Усі нові кнопки та елементи додаються у межах поточної дизайн-системи.

## Decisions

### 1. Додаткові типи ActionButtonBlock
Дозволити кнопкам `action_button` приймати наступні екшени:
*   `action: "add_to_cart"` (наявний)
*   `action: "navigate"` з пейлоадом `{ route: string }`
*   `action: "apply_filters"` з пейлоадом `{ retail_chain?: string, query?: string, category_slug?: string, price_min?: number, price_max?: number }`

*Альтернатива*: Створення окремого типу блоку для кожного екшену. *Рішення*: Використання єдиного типу `action_button` з дискримінатором `action` спрощує обробку у React-компонентах та Pydantic-схемах.

### 2. Видалення та очищення кошика
Агент спочатку отримує список кошиків користувача (`GET /cart/`), обирає перший (дефолтний), а потім:
*   Для очищення: викликає `DELETE /cart/{cart_id}/items`.
*   Для видалення товару: шукає товар за назвою серед елементів кошика, отримує його `item_id` і робить запит `DELETE /cart/{cart_id}/items/{item_id}`.

### 3. Оптимізація та порівняння всього кошика
Агент викликає `GET /cart/{cart_id}/compare`. Отримані дані містять інформацію про вартість усього кошика в різних мережах (Novus, Auchan, Metro, Ultramarket) та наявність товарів. Агент будує блок `table` з результатами порівняння та виділяє найвигідніший варіант, пропонуючи перенести товари туди.

### 4. Навігація та фільтрація на Фронтенді
У `AiChatWidget.tsx`:
*   При кліку на `action: "navigate"` викликається стандартний `navigate(payload.route)` з `react-router-dom`.
*   При кліку на `action: "apply_filters"` імпортується Zustand-стор каталогу, оновлюються відповідні поля фільтрів, чат автоматично закривається (`close()`), і користувач бачить відфільтровані товари.

## Risks / Trade-offs

- **[Risk]** Користувач не має кошика при спробі очищення або порівняння.
  - *Mitigation*: Агент спочатку перевіряє наявність кошиків. Якщо кошика немає, він створює дефолтний кошик ("Мій кошик") та повідомляє, що він порожній.
- **[Risk]** Товар для видалення має неоднозначну назву.
  - *Mitigation*: Агент порівнює назву за допомогою семантичного збігу або повертає блок `clarification` зі списком товарів, які дійсно є в кошику, пропонуючи вибрати потрібний.
