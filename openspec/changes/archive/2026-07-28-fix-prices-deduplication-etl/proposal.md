## Why

В таблице `prices` базы данных PostgreSQL продолжают накапливаться дубликаты записей цен при каждом перезапуске ETL-воркера (Go), даже если цена (`price`), старая цена (`old_price`) и наличие (`in_stock`) товара не изменялись. Это вызвано ограничением `recorded_at > NOW() - INTERVAL '3 hours'` в SQL-запросе, несоответствием типов чисел с плавающей точкой в Go (`float64`) с `NUMERIC(10,2)` в Postgres, а также отсутствием защиты от внутрипакетного (intra-batch) дублирования. 

Фикс необходим для предотвращения неограниченного роста таблицы `prices` (миллионы ненужных строк) и ускорения аналитических запросов.

## What Changes

- **Изменение логики проверки цен в Go ETL (`services/products_etl`)**:
  - Замена временного фильтра `NOW() - INTERVAL '3 hours'` на проверку **абсолютно последней записанной цены** (`ORDER BY recorded_at DESC LIMIT 1` / DISTINCT ON) для пары `(product_id, store_id)`.
  - Приведение типов при передаче параметров и сравнении: использование точного формата/приведения в SQL (`$3::numeric(10,2)` и `(old_price IS NOT DISTINCT FROM $4::numeric(10,2))`) или форматированного сравнения.
  - Дедубликация внутри текущего батча/страницы товара в Go перед формированием SQL batch-запроса (`pgx.Batch`).
- **Скрипт одноразовой очистки накопленных дубликатов**:
  - Запуск миграции/скрипта удаляющего последовательные дубликаты из существующей таблицы `prices`.

## Capabilities

### New Capabilities
- None

### Modified Capabilities
- `prices-deduplication`: Уточнение требования к Go ETL для сравнения с последней записью цены независимо от временного окна и предотвращения внутрипакетного дублирования.

## Impact

- **Affected Code**: `services/products_etl/internal/service/transformers.go`, `services/products_etl/database/migrate.go`
- **Database**: Таблица `prices`, индексы по `(store_id, product_id, recorded_at DESC)`
- **APIs & Systems**: Без негативного влияния на внешние API. Уменьшение объема БД и улучшение производительности чтения каталога.
