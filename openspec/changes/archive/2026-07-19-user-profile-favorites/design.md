## Context

Особистий кабінет користувача (`MainContent.tsx`) наразі використовує статичний масив `favoriteProducts` для відображення обраних товарів. При цьому в системі вже існує повноцінне схожість `useFavoritesStore` та бекенд-ендпоінти для управління обраними товарами (додавання, видалення, завантаження). Необхідно інтегрувати це сховище в профіль користувача, щоб відображати реальні дані.

## Goals / Non-Goals

**Goals:**
- Замінити статичні захардкоджені дані в блоці "Обрані товари" на динамічні дані з `useFavoritesStore`.
- Автоматично ініціювати завантаження обраних товарів при рендерингу профілю, якщо вони ще не були завантажені.
- Забезпечити коректну навігацію на сторінку товару при натисканні на картку товару.

**Non-Goals:**
- Реалізація пагінації чи додаткових фільтрів у блоці обраних товарів особистого кабінету.
- Редагування списку обраних безпосередньо зі сторінки профілю (це здійснюється через хедер або сторінки товарів).

## Decisions

### 1. Використання Zustand сховища `useFavoritesStore`
- **Рішення**: Імпортувати та підключити `useFavoritesStore` у компоненті `MainContent.tsx` модуля `Profile`.
- **Обґрунтування**: Це сховище вже повністю реалізоване, підключене до API та використовується в інших частинах додатку (наприклад, у хедері). Використання глобального Zustand-стейту запобігає дублюванню запитів та забезпечує реактивне оновлення інтерфейсу.

### 2. Запуск завантаження у `useEffect`
- **Рішення**: Викликати `loadFavorites()` у `useEffect` на сторінці профілю, якщо `isLoaded` дорівнює `false`.
- **Обґрунтування**: Це гарантує актуальність даних без зайвих повторних запитів, якщо дані вже завантажувалися раніше в межах сесії.

## Risks / Trade-offs

- **[Risk]** Уповільнення першого завантаження сторінки профілю при повільному з'єднанні.
  - *Mitigation*: Відображати легкий скелетон або лоадер (як для відгуків) під час завантаження списку обраних.
