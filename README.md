# 🛒 Smarket - Агрегатор цін

**Smarket** — це сервіс-агрегатор для порівняння цін на товари у різних ритейлерів. Цей проєкт побудований на архітектурі мікросервісів, що забезпечує гнучкість, масштабованість та незалежність компонентів.

---

## 🏗️ Архітектура

Система складається з наступних основних компонентів:

- **Frontend (`apps/react/frontend/my-react-app`)**: Клієнтський веб-застосунок на React + Vite + TailwindCSS.
- **API Gateway (`services/gateway`)**: Основна точка входу для фронтенду, яка маршрутизує запити до внутрішніх мікросервісів. (Порт: `8080`)
- **Business Logic Service (`services/api`)**: Ядро бекенду. Відповідає за товари, категорії, ритейлерів та кошики (FastAPI, Granian, SQLAlchemy). (Порт: `8000`)
- **Auth Service (`services/auth_service`)**: Мікросервіс для реєстрації, авторизації та керування користувачами (FastAPI). (Порт: `8001`)
- **Products ETL (`services/products_etl`)**: Воркер на Go для парсингу та отримання даних про товари. (Порт: `8082`)
- **Email Worker (`services/email_worker`)**: Воркер на Python для відправки електронних листів.
- **PostgreSQL (`db`)**: Єдина спільна база даних для всіх сервісів.
- **RabbitMQ (`rabbitmq`)**: Брокер повідомлень для асинхронної комунікації (наприклад, для ETL та Email Worker).

## 🚀 Швидкий старт (Локальний запуск)

Для розробки ми використовуємо Docker Compose, який підіймає всі необхідні сервіси та базу даних.

### 1. Запуск бекенду (Docker)
Відкрийте термінал і виконайте:
```bash
cd infra
docker compose up --build
```
*Ця команда підніме PostgreSQL, RabbitMQ, Gateway, Auth Service, Business Logic Service (з міграціями бази даних) та воркери.*

**Локальні адреси сервісів:**
- API Gateway (для фронтенду): http://localhost:8080
- Swagger UI (Business Logic API): http://localhost:8000/docs
- Swagger UI (Auth API): http://localhost:8001/docs
- PostgreSQL: `localhost:5432`

### 2. Запуск фронтенду
В іншому терміналі виконайте:
```bash
cd apps/react/frontend/my-react-app
npm install
npm run dev
```

## 📂 Структура проєкту (Монорепо)

Проєкт організовано як монорепозиторій.

```text
.
├── apps/               # Кінцеві застосунки (Frontend)
├── docs/               # Детальна технічна документація
├── infra/              # Інфраструктурний код (Docker Compose)
├── services/           # Бекенд-сервіси (Auth, API, Gateway, Workers)
│   ├── api/            # Business Logic Service (FastAPI)
│   ├── auth_service/   # Сервіс авторизації (FastAPI)
│   ├── email_worker/   # Воркер для відправки листів (Python)
│   ├── gateway/        # API Gateway
│   └── products_etl/   # Воркер для парсингу (Go)
├── .github/            # Налаштування CI/CD пайплайну
└── README.md           # Цей файл
```

## 🛠 CI/CD та Розробка

У репозиторії налаштовано єдиний CI пайплайн (`.github/workflows/ci.yml`), який автоматично:
1. Визначає мови програмування у змінених сервісах (Node.js, Python, Go, Docker).
2. Перевіряє код на наявність секретів та вразливостей.
3. Запускає відповідні лінтери, тести та збірки (паралельно).

Перед відправкою змін переконайтесь, що ваш код проходить перевірки локально!
