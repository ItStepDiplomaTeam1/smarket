# 🔌 Робочі ендпоінти бекенду SMARKET (для фронтенду)

Цей документ містить актуальний перелік та опис усіх активних HTTP-ендпоінтів бекенд-сервісів проекту **SMARKET**, які доступні для інтеграції з фронтенд-додатком (React / Next.js).

---

## 🚦 Загальна карта портів та адрес

У локальному Docker-середовищі сервіси доступні за такими адресами:

| Сервіс | Локальний URL | Опис |
| :--- | :--- | :--- |
| **API Gateway** | `http://localhost:8080` | **Основна точка входу для фронтенду.** Маршрутизує та перевіряє запити до внутрішніх мікросервісів. |
| **Business Logic Service** | `http://localhost:8000` | Ядро системи (продукти, категорії тощо). |
| **Auth Service** | `http://localhost:8001` | Сервіс авторизації та керування користувачами. |
| **Products ETL Service** | `http://localhost:8082` | Go-воркер для парсингу та отримання даних з Zakaz.ua. |

> 💡 **Рекомендація:** Фронтенд повинен виконувати всі запити через **API Gateway** (`http://localhost:8080`), окрім специфічних задач розробки чи прямого збору даних з ETL-воркера.

---

## 🛡️ 1. API Gateway (`http://localhost:8080`)

Гейтвей проксіює авторизаційні запити до сервісу авторизації, підтримує власну перевірку JWT та має тестовий проксі-маршрут для продуктів.

### 🟢 Системні запити

#### `GET /health`
*   **Опис:** Перевірка працездатності гейтвею.
*   **Автентифікація:** Не потрібна.
*   **Успішна відповідь (`200 OK`):**
    ```json
    {
      "status": "ok",
      "service": "Api Gateway"
    }
    ```

---

### 🔑 Авторизація (`/auth/*`)
Усі запити цієї групи проксіюються на `auth_service:8001` (окрім `/auth/me`, який перевіряється на рівні гейтвею).

#### `POST /auth/register`
*   **Опис:** Реєстрація нового користувача.
*   **Автентифікація:** Не потрібна.
*   **Rate Limits:** 3 запити на хвилину, 10 запитів на годину.
*   **Тіло запиту (`application/json`):**
    ```json
    {
      "email": "user@example.com",
      "password": "securepassword123"
    }
    ```
*   **Успішна відповідь (`201 Created`):**
    ```json
    {
      "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
      "token_type": "bearer",
      "email": "user@example.com"
    }
    ```
    *   *Примітка:* Сервер додатково встановлює **HttpOnly Cookie** `refresh_token` для автоматичного оновлення сесії (термін дії — 7 днів).

---

#### `POST /auth/login`
*   **Опис:** Авторизація користувача (вхід).
*   **Автентифікація:** Не потрібна.
*   **Rate Limits:** 5 запитів на хвилину, 20 запитів на годину.
*   **Тіло запиту (`application/json`):**
    ```json
    {
      "email": "user@example.com",
      "password": "securepassword123"
    }
    ```
*   **Успішна відповідь (`200 OK`):**
    ```json
    {
      "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
      "token_type": "bearer"
    }
    ```
    *   *Примітка:* Сервер встановлює **HttpOnly Cookie** `refresh_token` (термін дії — 7 днів).

---

#### `POST /auth/refresh`
*   **Опис:** Оновлення JWT `access_token` за допомогою `refresh_token`.
*   **Автентифікація:** Потребує наявності куки `refresh_token` у запиті.
*   **Успішна відповідь (`200 OK`):**
    ```json
    {
      "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
      "token_type": "bearer"
    }
    ```

---

#### `GET /auth/me`
*   **Опис:** Отримання базової інформації про поточного авторизованого користувача.
*   **Автентифікація:** **Обов'язкова** через заголовок `Authorization: Bearer <access_token>`.
*   **Успішна відповідь (`200 OK`):**
    ```json
    {
      "id": "a90b4d45-6677-44aa-bbcc-112233445566",
      "email": "user@example.com",
      "role": "user"
    }
    ```

---

#### `POST /auth/logout`
*   **Опис:** Вихід із системи. Видаляє авторизаційні файли куки.
*   **Автентифікація:** Не потрібна (видаляє `refresh_token` за будь-яких умов).
*   **Успішна відповідь (`204 No Content`):** Відповідь не містить тіла.

---

### 📦 Каталог товарів (Стаб гейтвею)

#### `GET /products`
*   **Опис:** Тимчасова заглушка проксі-маршруту для товарів.
*   **Автентифікація:** Не потрібна.
*   **Успішна відповідь (`200 OK`):**
    ```json
    {
      "message": "Products Proxy"
    }
    ```

---

## ⚡ 2. Products ETL Service (`http://localhost:8082`)

Go-сервіс, призначений для збору (парсингу) даних безпосередньо з джерел (Zakaz.ua) та керування завданнями імпорту.

### 🟢 Системні запити

#### `GET /health`
*   **Опис:** Перевірка працездатності Go-сервісу.
*   **Успішна відповідь (`200 OK`):**
    ```json
    {
      "status": "ok"
    }
    ```

#### `GET /docs/index.html`
*   **Опис:** Інтерактивна Swagger документація сервісу `products_etl`. Дозволяє тестувати парсинг у реальному часі.

---

### 🔄 Парсинг товарів

#### `GET /product/get`
*   **Опис:** Пряме отримання товарів з Zakaz.ua для певної торгової точки та категорії.
*   **Параметри запиту (Query params):**
    *   `store_id` (string, обов'язковий) — ID магазину (наприклад, `48215803` для Ашан).
    *   `category_id` (string, обов'язковий) — ID категорії (наприклад, `4820000` для бакалії).
*   **Успішна відповідь (`200 OK`):**
    Повертає повний оригінальний масив товарів від Zakaz.ua (з чистими описами без HTML та реальними вагами відповідно до версії API v39/v29).

---

## 🏗️ 3. Business Logic Service (`http://localhost:8000`)

Головний мікросервіс на Python (FastAPI), що працює з сутностями бази даних (користувачі, категорії, продукти, ціни, кошики).

### 🟢 Системні запити

#### `GET /health`
*   **Опис:** Перевірка працездатності сервісу бізнес-логіки.
*   **Успішна відповідь (`200 OK`):**
    ```json
    {
      "status": "ok"
    }
    ```

---

### 🛍️ Управління продуктами (`/products`)

#### `POST /products`
*   **Опис:** Додавання нового продукту в локальну базу даних.
*   **Автентифікація:** Не потрібна.
*   **Тіло запиту (`application/json`):**
    ```json
    {
      "name": "Молоко Селянське 2.5%",
      "category_id": "84fd8d88-8123-4929-8fb8-cbfdf4939a31",
      "external_id": "ean-4820002130098",
      "general_description": "Ультрапастеризоване питне молоко",
      "specifications": {
        "fat_percentage": 2.5,
        "volume": "900г"
      }
    }
    ```
    > ⚠️ *Примітка:* `category_id` має бути дійсним UUID категорії, що вже існує в базі даних (наприклад, створені під час міграцій/сівінгу категорії: Електроніка, Побутова техніка, Смартфони тощо).
*   **Успішна відповідь (`201 Created`):**
    ```json
    {
      "id": "ef2d8b4e-4f51-419b-bf72-bd242bfdf521",
      "name": "Молоко Селянське 2.5%",
      "category_id": "84fd8d88-8123-4929-8fb8-cbfdf4939a31",
      "external_id": "ean-4820002130098"
    }
    ```

---

#### `DELETE /products/{product_id}`
*   **Опис:** Видалення продукту з бази даних за його ідентифікатором.
*   **Параметри шляху (Path params):**
    *   `product_id` (UUID, обов'язковий) — Унікальний ідентифікатор продукту в системі SMARKET.
*   **Успішна відповідь (`204 No Content`):** Тіло відповіді порожнє.
*   **Помилки:**
    *   `404 Not Found` — якщо продукт з таким ID не існує.
