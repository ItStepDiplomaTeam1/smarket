# 📦 Документація Ендпоінтів Продуктів SMARKET

У цьому документі наведено детальний аналіз та опис усіх поточних HTTP-ендпоінтів для роботи з продуктами та магазинами у проєкті **SMARKET**.

---

## 🏗️ Загальний опис архітектури продуктів

Робота з товарами у системі розбита на 4 основні компоненти:
1. **API Gateway (Шлюз)**: Приймає всі запити від фронтенду за адресою `/api/v1/...` та проксує їх на відповідні мікросервіси. Також шлюз відповідає за авторизацію та перевірку ролей (наприклад, дозволяє створення/видалення продуктів тільки користувачам із роллю `admin`).
2. **Product Catalog Service (`product_service`)**: Публічний **Read-Only** каталог. Використовує базу даних, яку наповнює Go ETL-воркер. Отримує миттєві сповіщення про оновлення через механізм `PostgreSQL LISTEN/NOTIFY` та передає актуальну інформацію на фронтенд.
3. **Product Core API (`business_logic_service` / `api`)**: Внутрішній сервіс для **запису/видалення** товарів адміністраторами (CRUD). 
4. **Products ETL Worker (`products_etl` на Go)**: Фоновий сервіс, що автоматично парсить товари з зовнішнього API Zakaz.ua, зберігає сирі дані в MongoDB, структурує їх і переносить у PostgreSQL, надсилаючи `pg_notify` про оновлення цін чи наявності.

---

## 🔑 Безпека та маршрутизація на API Gateway

*   **GET-запити** (перегляд товарів та магазинів): Проходять через Gateway анонімно, без обов'язкової авторизації.
*   **POST/PUT/DELETE-запити** (модифікація): Вимагають обов'язкової авторизації через заголовок `Authorization: Bearer <JWT_TOKEN>`.
    *   Шлюз декодує JWT-токен за допомогою `JWT_SECRET_KEY`.
    *   Перевіряє поле `role` в токені. Якщо `role != "admin"`, повертається помилка `403 Forbidden`.
    *   Якщо користувач є адміном, шлюз збагачує запит заголовками `X-User-Id` та `X-User-Role` і передає його далі.

## 📖 1. Публічний Read-Only каталог товарів (`product_service`)
Всі запити проксуються через Gateway з префіксом `/api/v1/products`.

### ➡️ `GET /api/v1/products/` — Отримання загального списку товарів
Повертає глобальний каталог товарів з дедуплікацією по EAN, підтримує фільтрацію, пошук і пагінацію.

*   **Тип запиту:** `GET`
*   **Вхідні параметри (Query params):**
    | Параметр | Тип | Обов'язковий | Опис |
    | :--- | :--- | :--- | :--- |
    | `skip` | `int` | Ні (default: 0) | Кількість записів для пропуску (пагінація) |
    | `limit` | `int` | Ні (default: 100) | Ліміт записів у відповіді (макс. 1000) |
    | `brand` | `str` | Ні | Фільтр за назвою бренду (частковий збіг, без урахування регістру) |
    | `category_id` | `int` | Ні | Фільтр за канонічним ID категорії |
    | `search` | `str` | Ні | Пошук за назвою товару (частковий збіг) |
    | `store_id` | `str` | Ні | Фільтр за магазином (покаже товари, що продаються у вказаному магазині) |

*   **Формат вихідних даних (JSON):** Список об'єктів `ProductResponse`
    ```json
    [
      {
        "id": 123,
        "ean": "4820000123456",
        "store_product_id": "prod-109283",
        "title": "Молоко 2.5% ультрапастеризоване",
        "brand": "Яготинське",
        "unit": "кг",
        "weight": 0.9,
        "image_url": "https://image.zakaz.ua/...jpg",
        "canonical_category_id": 5,
        "created_at": "2026-06-17T15:30:00Z"
      }
    ]
    ```

### ➡️ `GET /api/v1/products/by-store/{store_id}` — Каталог конкретного магазину з актуальними цінами
**Ключовий ендпоінт для фронтенду.** Повертає список товарів конкретного магазину разом із останньою актуальною ціною для кожного з них.

*   **Тип запиту:** `GET`
*   **Параметри шляху (Path params):**
    *   `store_id` (`str`): Зовнішній ID магазину на Zakaz.ua (наприклад: `"48215803"`).
*   **Вхідні параметри (Query params):**

    [
      {

## 3. Адмін-ендпоінти створення та видалення продуктів (`business_logic_service` / `api`)
Ці ендпоінти виконують фізичний запис та видалення з основної БД. Вони вимагають прав адміністратора (`role == "admin"` у JWT-токені) на рівні шлюзу.

> [!WARNING]
> Ендпоінти використовують модель ідентифікатора у форматі **UUID** для первинних ключів товарів, на відміну від публічного каталогу, де ID є цілим числом (`int`).

### ➡️ `POST /products` — Створення нового продукту
Створює запис про новий канонічний продукт у базі даних.

*   **Тип запиту:** `POST`
*   **Авторизація:** Обов'язково `Bearer <Token>` (тільки адмін).
*   **Вхідні дані (JSON Body):**
    ```json
    {
      "name": "iPhone 16 Pro Max",
      "category_id": "9b1deb4d-3b7d-4bad-9bdd-2b0d7b3dcb6d",
      "external_id": "iph16promax-512",
      "general_description": "Смартфон Apple iPhone 16 Pro Max 512GB Black",
      "specifications": {
        "storage": "512GB",
        "color": "Black Titanium",
        "ram": "8GB"
      }
    }
    ```
*   **Вихідні дані (JSON, `201 Created`):**
    ```json
    {
      "id": "e30e6284-cb0d-4007-9b2f-9819777f98e6",
      "name": "iPhone 16 Pro Max",
      "category_id": "9b1deb4d-3b7d-4bad-9bdd-2b0d7b3dcb6d",
      "external_id": "iph16promax-512"
    }
    ```

---

### ➡️ `DELETE /products/{product_id}` — Видалення продукту
Видаляє товар з бази даних за його унікальним UUID.

*   **Тип запиту:** `DELETE`
*   **Авторизація:** Обов'язково `Bearer <Token>` (тільки адмін).
*   **Параметри шляху (Path params):**
    *   `product_id` (`UUID`): Ідентифікатор товару.
*   **Вихідні дані:** `204 No Content` (успішно видалено, без тіла відповіді).
*   **Помилки:** `404 Not Found` (якщо товар не знайдено).

*   **Вхідні параметри (Query params):**

    *   `category_id` (`str`, обов'язковий): ID категорії на Zakaz.ua (напр. `"4820000"`).
*   **Вихідні дані:** Сирий JSON відповіді від Zakaz.ua.

## ⚠️ Важливе спостереження / Архітектурний нюанс

У конфігураційних файлах помічено потенційну невідповідність (можливий баг), яку варто врахувати при налаштуванні середовища:

В описі `services/gateway/app/api/core/config.py` за замовчуванням встановлено:
```python
PRODUCT_SERVICE_URL: str = "http://business_logic_service:8000"
```
Однак у файлі реальних змінних оточення `services/gateway/.env` прописано:
```env
PRODUCT_SERVICE_URL=http://product_service:8000/api/v1/products
```

**Що це означає:**
Оскільки `.env` перезаписує значення з `config.py`, то **всі** запити на шлюзі до `/api/v1/products/...` (включаючи `POST` та `DELETE`) направляються у сервіс `product_service:8000/api/v1/products`.
1. Для `GET`-запитів це працює чудово, адже `product_service` відповідає за перегляд каталогу.
2. Проте, якщо адміністратор спробує зробити `POST /api/v1/products` (створити продукт) або `DELETE /api/v1/products/{id}`, шлюз спробує надіслати цей запит у `product_service`, де таких методів **не існує** (вони є тільки у `business_logic_service`). Запит поверне помилку `405 Method Not Allowed`.

**Рішення:**
Шлюз повинен розділяти запити на читання (проксувати в `product_service`) та запити на зміну (проксувати в `business_logic_service`), або ж конфігурація `PRODUCT_SERVICE_URL` у `.env` шлюзу має бути скоригована.
