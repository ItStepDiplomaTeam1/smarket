# 📑 Аналіз та опис API Zakaz.ua для SMARKET

Цей документ містить детальний аналіз та структурування API сервісу **Zakaz.ua**, розподілений на логічні блоки відповідно до потреб сервісу імпорту товарів (**products_etl**).

---

## 1. 🎯 Критично важливі ендпоінти для воркера (`products_etl`)

Ці ендпоінти складають ядро нашого парсера. Вони використовуються для циклічного збору інформації про магазини, категорії, товари та актуальні ціни.

### 🗺️ Схема пайплайну збору даних

```text
                      [ СТАРТ ПАЙПЛАЙНУ ]
                              │
                    GET /stores/ (v48, v45)
                              │
            ┌─────────────────┴─────────────────┐
            ▼                                   ▼
 GET /stores/{id}/categories/       GET /stores/{id}/products/{ean}/
            │                                (v48, v41)
            ▼
 GET /stores/{id}/categories/{id}/products/
      (v49, v48, v39, v29)
```

### 📋 Детальний опис ендпоінтів

| Метод та ендпоінт | Версії | Опис та значення для `products_etl` |
| :--- | :--- | :--- |
| `GET /stores/`<br>або `GET /stores/{store_id}/` | `v48`, `v45` | **Отримання списку або конкретного магазину.**<br>Повертає список доступних торгових точок (Ашан, Новус, Метро тощо) та детальну інформацію про них.<br>⚠️ **Важливо:** Починаючи з версії **v45**, додано поле `service_fee_percentage` (відсоток сервісного збору). Його обов'язково потрібно зберігати в Postgres для коректного розрахунку фінальної вартості кошика на бекенді. |
| `GET /stores/{store_id}/categories/{category_id}/products/` | `v49`, `v48`, `v39`, `v29` | **Головний робочий маршрут парсингу.**<br>Повертає пагінований список товарів у конкретній категорії обраного магазину.<br>💡 **Підказка (v39):** Повертає опис товару без HTML-тегів. Це спрощує Go DTO мапінг (не потрібно писати регулярні вирази для очищення від `<p>`, `<br>` тощо).<br>💡 **Підказка (v29):** У полі `weight` повертається чиста реальна вага продукту, а не абстрактний об'єм. |
| `GET /stores/{store_id}/products/{ean}/` | `v48`, `v41`, `v39`, `v29` | **Отримання товару за штрихкодом (EAN).**<br>Критично для матчингу товарів між різними мережами (наприклад, порівняння цін на однакове молоко в Ашані та Novus). |
| `GET /stores/{store_id}/products/search/`<br>*(або search_old, quick_search)* | `v49`, `v48`, `v39`, `v29` | **Повнотекстовий пошук по каталогу.**<br>Використовується як резервний механізм, якщо категорійний парсинг пропустив певний товар. |
| `GET /stores/{store_id}/products/promotion/` | `v49`, `v48`, `v39`, `v29` | **Список акційних товарів.**<br>Повертає виключно позиції зі знижками. Дозволяє швидко оновлювати `discount_price` (акційні ціни) поза основним колом парсингу. |
| `GET /stores/{store_id}/products/{ean}/recommended/`<br>та `/similar/` | `v48`, `v39`, `v29` | **Рекомендовані та схожі товари.**<br>Збір цих зв'язків дозволяє наповнювати таблиці рекомендацій в Postgres для відображення блоку *"З цим товаром також купують"* на фронтенді. |

## 2. 🛒 Кошик та замовлення
> ℹ️ **Не потрібні для воркера products_etl.** Ці ендпоінти обробляються клієнтом для керування покупками.

*   `GET /cart/` — Отримання поточного стану кошика користувача.
*   `POST /cart/items/` — Додавання/видалення товарів у кошику (з версії `v37` підтримує коментарі для пікера/складальника).
*   `POST /cart/delivery/` — Вибір методу доставки (у `v56` дані отримувача перенесені в корінь JSON).
*   `POST /cart/time_window/` — Вибір часового слоту доставки.
*   `POST /cart/payment/` — Вибір методу оплати (в `v58` додано автооплату `card_online_auto`).
*   `POST /cart/contacts/`, `/replacements/`, `/packing/` — Налаштування контактних даних, правил заміни відсутніх товарів та типу пакетів.
*   `POST /cart/coupon/` — Прив'язка промокоду.
*   `POST /cart/clear/` та `/full_clear/` — Очищення позицій кошика.
*   `POST /cart/checkout/` — Фінальне оформлення замовлення (чекаут). З версії `v43` автоматично розділяє замовлення на два окремих чека, якщо в кошику є підакцизні товари (алкоголь/тютюн).
*   `POST /stores/{store_id}/cart/` та `/orders/` — Створення кошика та замовлення в контексті конкретного магазину для неавторизованих або застарілих сесій.

## 3. 👥 Авторизація та профіль користувача
> ℹ️ **Не потрібні для воркера products_etl.** Використовуються виключно для взаємодії користувача з додатком.

*   `POST /user/login/` — Аутентифікація за допомогою пароля або Bearer токена.
*   `POST /user/confirm_login/` — Підтвердження входу (SMS/OTP код).
*   `POST /user/signup/` та `/confirm_signup/` — Реєстрація нового акаунту та її підтвердження.
*   `POST /user/password_recovery/` — Запит на відновлення пароля.
    > ⚠️ **Примітка з v31:** Має жорсткий Rate Limit. У разі частих запитів сервер повертає `429 Too Many Requests` з хедером `Retry-After`.
*   `GET /user/profile/` — Отримання даних поточного профілю (у `v54` видалили поле `registered`).
*   `POST /user/profile/phones/` та `/phones/login/` — Керування номерами телефонів у профілі користувача.
*   `GET /user/app-widget/` — Дані активного замовлення для віджета мобільного додатка або робочого столу.
*   `GET /user/lists/` та `GET /user/lists/{shopping_list_id}/` — Списки покупок користувача ("Обране", "Купити пізніше").

## 4. 📦 Логістика, географія та доставка
> ℹ️ **Не потрібні для воркера products_etl.** Відповідають за інтеграцію з логістичними провайдерами.

*   `GET /delivery/settlements/` — Список населених пунктів, куди здійснюється доставка.
*   `GET /delivery_services/{delivery_service_id}/` — Інформація про служби доставки (замінила старі ручки міст та регіонів у версії `v46`).
*   `GET /delivery_third_party/nova_poshta/settlements/{id}/warehouses/` — Список відділень та поштоматів Нової Пошти для вибраного населеного пункту (підтримує фільтрацію `type=postomat`).
*   `GET /delivery_types/` та `/user/delivery_presets/` — Доступні типи логістики (самовивіз, кур'єр, Нова Пошта) та збережені шаблони адрес клієнта.
*   `GET /user/delivery_schedule/` або `/stores/{id}/delivery_schedule/{method}` — Вікно вибору доступних годин доставки (з версії `v55` підтримує параметр `slot_types=open` замість застарілого `only_open`).

---

## 5. 📄 Контент, маркетинг та інші ендпоінти
> ℹ️ **Не потрібні для воркера products_etl.**

*   `GET /stores/{store_id}/service_pages/` та `/{page_id}/` — Інформаційні сторінки магазину (умови повернення, контакти адміністрації, правила акцій).
*   `/promotions/*` — Маркетингові банери та промо-кампанії.
*   `POST /user/orders/{order_id}/quick_feedback/` — Форма швидкого фідбеку після отримання замовлення (оцінка збору продуктів, скарги на зіпсовані товари).
*   `GET /user/orders/{order_id}/notifications/` та `/notifications_statistic/` — Отримання сервісних повідомлень по замовленню та внутрішній чат із кур'єром/пікером.
*   `/stores/{store_id}/recipes/` та `/{recipe_id}/` — Кулінарні рецепти, інтегровані в магазин.
    > 💡 **Примітка з v19:** Користувач може в один клік додати всі інгредієнти рецепта до кошика. Повертає масив посилань на зображення різних розмірів (`s200x200`, `s350x350`).

## 💡 Висновок для розробки

Під час розробки клієнта запитів (`MakeRequest`) та планування логіки в `main.go` для **products_etl**, слід зосередитися **виключно на Ендпоінтах з Розділу 1**.

Завдяки детальному аналізу версій та змін:
1. Запити до товарів категорій (`/categories/{id}/products/`) повертають очищені тексти описів товарів без HTML-тегів, що значно спрощує Go DTO мапінг.
2. Обов'язково потрібно зчитувати та зберігати поле `service_fee_percentage` під час оновлення інформації про магазини (`/stores/`), оскільки воно впливає на фінальну ціну для кінцевого користувача SMARKET.
